# 规划 Cocos Prefab 节点树

将提示中的视觉与功能需求转成唯一、可验证的 Prefab 节点蓝图，再按需交给现有 Cocos Creator 3.8 技能拼装。不要把效果图复述当成节点规划。

## 工作流

1. 收集证据。
   - 读取用户提示、效果图尺寸和可见内容。
   - 若有 Cocos 工程，先查看相邻 Prefab、通用控件、命名习惯、设计分辨率和可复用资源。
   - 若有现有 Prefab，使用 `inspect-cocos-content` 或 `control-cocos-editor` 查询实际层级，不凭文件名推断。
2. 判断交付模式。
   - “分析、设计、规划”只输出蓝图，不修改工程。
   - “创建、制作、拼装、实现”先形成蓝图，再使用 `assemble-cocos-ui` 及其依赖技能实际创建并验收。
   - 用户只提供部分信息时继续做安全规划，将影响结构的未知项列为“待确认”，不要虚构。
3. 将需求归一化为功能区域、渲染层、动态数据、交互、重复项、滚动/裁剪关系、互斥状态和适配约束。
4. 先确定容器与状态边界，再设计叶子视觉节点。使用 [references/blueprint-rules.md](references/blueprint-rules.md) 中的组件选择和拆分规则。
5. 生成节点蓝图。节点规格表是尺寸、位置、锚点和组件属性的唯一事实来源；树状结构只表达父子关系、顺序和组件概览。
6. 执行蓝图一致性检查，修复冲突后再展示或拼装。
7. 若需拼装，按“根容器 → 功能容器 → 叶子节点 → 组件属性 → 引用关系 → Layout/Widget 更新”的顺序执行。创建期间按完整节点路径追踪节点，不使用模糊简称。
8. 拼装后使用 `assemble-cocos-ui` 的布局检查与 UI 校验，比较实际 Prefab 和蓝图；只在校验通过后报告完成。

## 分析原则

- 以实际证据为准：提示明确值 > 工程现有约定 > 效果图测量 > 标注为“估算”的推断。
- 默认使用英文 PascalCase 节点名。禁止 `Node001`、`Image1`、`Text2` 等无语义名称。
- 静态背景、动态内容、交互热区、状态组、特效/引导分层；节点顺序体现从后到前的渲染顺序。
- 只为布局、定位、裁剪、动画、状态控制或复用增加容器。不要为对齐制造空节点。
- 动态换图、换色、改文字、显隐、缩放或动画的元素必须可独立控制。
- 重复结构只详细定义一个 `ItemTemplate`；说明运行时数量，不在 Prefab 中堆出未知数量的副本。
- 大范围视觉差异可用独立状态组；仅属性不同的状态共用节点并列出属性变化。
- 不输出脚本字段、事件回调、资源切图清单，除非用户明确要求。

## 蓝图输出

默认按以下顺序输出，字段定义和表格模板见 [references/output-template.md](references/output-template.md)：

1. 分析摘要与设计基准
2. 完整 Prefab 节点树
3. 关键节点规格表
4. Sprite 与 Label 配置
5. Button、Toggle、滚动与裁剪配置
6. 界面状态表
7. Widget 与分辨率适配表
8. 拼装顺序
9. 待确认项和带依据的估算

保持输出可执行：

- 为每个节点给出完整且唯一的路径。
- 为所有 UI 节点配置 `UITransform`；即使树中为简洁省略，也必须在规格表中体现。
- 尺寸和位置使用相对于父节点的本地坐标；注明设计分辨率和单位。
- 明确默认激活状态、动态性、可点击性、动画需求以及数据重复关系。
- 对 `ScrollView` 明确 `View/Mask/Content` 引用，对 `ProgressBar` 明确 `barSprite`，对 `Toggle` 明确 check mark 与容器关系。
- 对无法从证据确定的值填写“待确认”；可合理测量时填写“估算：数值”，不要用无标记的假精确值。

## 一致性检查

在交付或拼装前逐项确认：

- 树中每个路径唯一，父路径存在，命名符合规则。
- 规格表覆盖所有关键节点，且与树中的组件一致。
- 同一轴上没有 `Layout`、`Widget` 和手动坐标/尺寸的控制冲突。
- `Mask` 是被裁剪内容的祖先；`ScrollView` 的 View、Content 和滚动方向完整。
- Button 根节点承担点击区域，视觉节点位于其下；点击区不小于视觉区。
- 状态互斥关系、默认状态、动态模板和最高渲染层明确。
- SLICED 图只拉伸允许变形的中心区域；人物、图标和复杂花纹不做非等比拉伸。
- 全屏、顶部、底部、居中与安全区策略覆盖目标宽高比。
- 所有“估算”和“待确认”均集中列出，未混入确定事实。

## 拼装约束

- 复用项目已有 Prefab 与资源，不创建仅名称相似的重复控件。
- 优先通过编辑器桥接和 AssetDB 修改资源；不要手写 Creator 序列化对象 ID、UUID 或 `.meta`。
- 未指定 Layer 时使用 `UI_2D`（`33554432`）。
- 未提供美术资源且用户要求先完成结构时，允许使用引擎默认 SpriteFrame 与明显的占位颜色；将占位项报告出来。
- 分阶段保存和校验复杂界面。出现 error 时先修复；warning 必须解释或修复。
