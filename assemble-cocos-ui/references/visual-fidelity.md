# 效果图一致性与纯色占位验收

输入包含效果图时，本参考是强制流程。目标是在效果图对应的分辨率和内容状态下还原界面，同时保持界面可交互、可维护并符合工程运行时契约。美术资源是否提供决定视觉元素的验收方式。

## 资源模式判定

对效果图中的每个视觉元素分别判定：

- 用户提供、蓝图明确指定，或工程中已确认唯一对应资源的元素使用精确素材模式。必须绑定该 SpriteFrame、字体或 Prefab，并接受严格像素验收。
- 没有提供对应美术资源，也无法确认唯一工程资源的元素使用纯色占位模式。使用中性纯白 SpriteFrame 配合 `Sprite.color`，按效果图的大致形状、尺寸、位置和层次拼装。
- 同一界面允许两种模式并存。已有资源的元素不能因为其他元素缺资源而降级成纯色或近似素材。

纯色占位只能代表缺失的美术元素。不要使用带 Logo、花纹或图案的默认图，不要寻找风格相近的插画冒充原图，也不要把效果图截图裁块后导入。每个纯色节点都要记录原图区域、占位颜色和待替换资源用途。

## 固定比较基线

保留用户提供的原图，不裁剪、不缩放、不二次压缩。开始拼装前记录：

- 原图像素宽高、方向、色彩模式和透明通道。
- 设计分辨率、适配策略、设备像素比、横竖屏和安全区。
- 当前语言、字体、文案、数值、头像/图标、列表数量与滚动位置。
- 所有状态组的当前分支、节点显隐、按钮状态、进度值和遮罩范围。
- 动画或粒子对应的准确时间点。无法固定帧时，先暂停或把进度设为确定值再截图。

参考图和实测图必须使用同一个基线。尺寸、语言、数据或动画帧不同的两张图不能进入像素比较。

## 从图像建立可执行规格

按从外到内的顺序测量画布、全屏背景、主面板、功能区域、重复项和叶子视觉。对每个可见元素记录：

- 左、上、宽、高和中心点，以原图左上角为原点。
- 与父容器和相邻元素的水平/垂直间距。
- SpriteFrame、九宫格边界、裁剪方式、混合颜色和透明度。
- 字体资源、字号、行高、字距、对齐、Overflow、描边、阴影和字符串。
- 激活状态、层级顺序以及是否受 Layout、Widget、Mask 或动画控制。

当根节点锚点为 `(0.5, 0.5)`、节点锚点也为 `(0.5, 0.5)` 时，可把图像坐标换算为根节点本地坐标：

```text
x = left + width / 2 - canvasWidth / 2
y = canvasHeight / 2 - (top + height / 2)
```

锚点不为中心时按实际锚点换算，不能先用中心坐标拼装后再靠目测拖动。

## 素材与文字

- 先从效果图识别素材，再核对用户提供资源、AssetDB、相邻 Prefab、公共 Prefab 和图集。能确认完全对应的资源进入精确素材模式；不能确认时进入纯色占位模式。名称相似但轮廓、留白、九宫格或颜色不同的资源不能替代。
- 复用 SpriteFrame 时保留原始 trim、旋转、九宫格和采样设置。不要用缩放补偿错误留白。
- 人物、图标和复杂纹理保持等比缩放；只有设计为可拉伸区域的底板和条形背景使用 SLICED。
- 已提供字体时必须使用效果图对应的字体文件和渲染参数。字体未提供时可用项目默认字体拼装大致排版，并把字体列入待替换项；不能把近似字体结果称为完全一致。
- 动态文字用固定测试数据复现参考状态。不要把文字烘焙进背景图来通过比较。

## 真实渲染

静态 Prefab 使用 `cocos-prefab-preview`，输出宽高与效果图像素尺寸相同。界面依赖业务数据、Widget/SafeWidget、运行时换图、动画或特效时，使用 `capture-cocos-runtime`，并先把运行状态固定到参考图对应状态。

所有对比产物写入目标工程 `temp/assemble-cocos-ui/`。禁止用编辑器截图、设计工具预览或手工合成图代替 Creator 的真实渲染结果。

## 差异迭代顺序

精确素材模式下，每轮真实渲染后运行 `scripts/compare-ui-images.py`，同时生成差异图、50% 叠图和 JSON 报告。纯色占位模式可用叠图和差异边界校正几何，但不要求占位区域像素相同。按下面顺序修正，避免在父级几何仍错误时微调子节点：

1. 画布尺寸、根节点缩放、适配和整体偏移。
2. 主面板与功能区域的位置、尺寸、锚点和间距。
3. SpriteFrame、SLICED 边界、Mask、裁剪和渲染顺序。
4. 字体、字号、行高、对齐、描边、阴影和字符串。
5. 颜色、透明度、材质、混合模式和抗锯齿来源。
6. 单像素边缘、半像素坐标、细小间距和最终 RGBA 差异。

查看报告中的 `mismatchBounds`、`topMismatchRows` 和 `topMismatchColumns` 定位主要偏差。每次只改有证据指向的属性，重新更新 Layout/Widget、保存、渲染和比较。

## 完成门槛

全部视觉元素都有对应资源时，同时满足以下条件才能报告完全一致：

- 参考图与真实渲染图像素宽高完全相同。
- 比较报告 `mismatchPixels` 为 0，`maxChannelDifference` 为 0。
- 没有占位素材、临时文字、缺失字体或未固定的动态内容。
- 可交互元素仍是独立节点，并保留 MButton、ReferenceCollector、Switch、ScrollView 等工程契约。
- 未把整张效果图或局部大截图作为覆盖层隐藏真实 UI。

存在未提供的美术或字体资源时，可以报告“大致效果拼装完成”，但必须同时满足：

- 只有缺失资源对应的元素使用纯色 Sprite 或项目默认字体。
- 已有资源、界面结构、节点尺寸、位置、间距、层级、文字内容和交互均已验收。
- 交付清单列出每个纯色节点、默认字体节点和所需的最终资源。
- 没有把近似结果描述为完全一致，也没有为通过像素检查而降低阈值。
